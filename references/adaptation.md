# 网文改编

按“确定本次任务 → 原文分块与读取 → 必要分析和方案 → 每批 20 场写作 → 检查与保存”执行。只走本次需要的阶段，已有有效成果直接复用。目录使用 [workspace-layout.md](workspace-layout.md)，状态记录使用 [project-records.md](project-records.md)。

## 先判断用户要哪一步

| 本次要求 | 执行范围 |
| --- | --- |
| 先拆分、先处理开头若干字/章 | 只机械拆分、保存来源清单与素材索引；不把拆分当分析，不起草改编正文 |
| 分析、预计能改多少场/多少字 | 读取所需原文后分析或给有依据的区间估算；场数不是章数，估算不是最终承诺 |
| 首次写正文 | 先完成创作方案，按 SKILL.md 取得确认或明确跳过；已有确认方案直接复用 |
| 继续下 20 场或一次写更多场 | 接当前指定版本，按 [batch-writing.md](batch-writing.md) 在当前会话每批最多 20 场串行完成，不新建子代理 |
| 先想想改哪里、融什么梗、给候选 | 只给定位、原因和候选对白/动作，保存到 `方案/修改候选_版本_范围.md`；不顺手改正文 |

写作期间用户明确改为“先思考、先讨论”时，先记录原任务已经保存的场次、尚未核验范围和下一步，暂停正文写入及润色，处理新的讨论范围。讨论不是批准候选；明确要求落实后再按指定范围改稿。“只改这里”也不授权顺带润色整批。

## 原文分块：按章，不把章改叫场

先看素材索引及原文件章节结构，区分全书、已拆分、已读和本批需要的范围。原文很长时，先用脚本扫描章节标题和位置，按实际原章每五章保存一份至 `参考素材/来源/原文拆分/`，末组不足五章按实际范围命名；用户另有分组要求时遵从。扫描标题不表示已读正文。

用户指定“约五万字”等范围时，以最接近目标的完整章节边界截取并报告实际数量；明确要求不超过时选上限内的完整章节。说明字数口径，不把非空白字符数称为纯汉字数。这是用户指定的原文阅读窗口，不是所有改编都必须先读五万字。

拆分保留原文和章号，不润色、不摘要替换；清单记录源文件版本/指纹、章节标题与定位、各文件范围、下一章起点。核对拼接可还原所选原文、无遗漏或重复、源文件未变。复用现有可用脚本；需要编写时放入来源的 `工具/`，只负责拆分和拆分清单，不能重写创作项目索引或确认状态。重跑不得覆盖不同版本的已有成果。

无可靠章节标记时用原有段落或可回查位置分块并说明，不编造章号。没有正文只有大纲时按大纲改编，明确资料边界。

## 读取与最小必要分析

完整读取本批对应章段；事件跨分块时补齐起因和结果，后文只按承接需要扩读。工具输出截断时补读缺段，不以文件名、字数统计或章节清单冒充已读原文。同一会话中已实际读到且仍可用、版本未变的内容直接复用；压缩后按索引恢复必要内容。

来源分析保存在 `参考素材/来源/分析/`：人物与核心设定、主线总览和本批需要的证据。按原著章段定位，不为了套“五场概括”把小说章节冒称短剧场次。五场概括用于已经存在的剧本场次。区分原著事实、分析判断、用户指定修改及拟新增内容，只补当前缺项，不每批重做全书分析。

先确认主角想得到什么、阻力来自哪里、观众期待什么，以及关键场面的前置条件。保留角色稳定性格和行为选择、关系性质与成长过程；亲属合作、生活压力、资源获取等按实际原著处理，不为短剧化统一增加恶亲戚、村霸或受辱打脸。

有指定对标案例时按 [case-alignment.md](case-alignment.md) 选取本批阶段的完整事件；没有案例不额外寻找。未授权剧情重构时，原著提供剧情，案例提供指定写法；用户明确融合时才重构剧情和关系，并标明各来源贡献。

## 方案与本批安排

首次方案按 SKILL.md 包含大纲、核心主线、人物关系、世界观与改编取舍，存入 `方案/创作方案_版本.md`，确认状态登记项目索引。局部原著只能支持该范围的规划，未读后文和连载未完结处不编造原作结局。估算后续场数、字数时给出依据与可调整区间，不反向凑字数、固定每章场数或把每场强行写成一集。

获准正文后，只细化当前最多 20 场的章段对应，保留整体阶段方向；对应记录保存在 `稿件资料/版本/写作对应/第A-B场.md`。同一文件先记规划，出稿后补实际落地与必要修正，不另造多套“安排、写前、写后、最终”文件。

每场简记原著章段、本场行动与结果、改编处理及下一场承接。合章、拆章、前移与删并按戏剧作用安排：

1. 保留承担立人、关系变化、情绪积累或兑现的事件；重复说明可压缩，不能省掉关键铺垫。合并人物须在授权范围内核对身份、动机及知情。
2. 用完整交锋和局面变化确定场界，按用户实际要求组织集界；没有付费卡点要求不额外设置。章、场、集分别计数。
3. 重排时检查人物当时知不知道、能不能做、为什么现在做；新增行动来自已有设定和动机，不靠突然来人或凭空物证补因果。
4. 将内心、前世履历、背景知识转成可见行动、反应和必要的短信息；专业知识只保留影响当下选择的部分，不改成角色讲课。

## 串行起草与回查

承接写作先按 continuation.md 与 batch-writing.md 读取工作底稿首尾正文、中间概括及必要原场，最近窗口落在上一批工作稿结尾。已确认方案不因换批重复确认。总请求中的后批可承接同一待采用版本，自动串联不等于用户采用；另一次明确“接着这版继续”的采用依据按 SKILL.md 记录。

每批按 `script-format.md` 写完整正文至 `正文/版本/第A-B场.txt`，不以梗概替代。核对人物选择、因果、对白、时空、知情、物资变化和原著对应；按 checks.md 修正本批实际问题。

事实核对要区分“原著已证实矛盾”和“自己的理解还不完整”：数字有疑问时先回读类别、单位、前提与上下文，不能仅凭推算判原著漏账。对白中的夸张、口语省略和人物误解按情境判断，不把顺口台词机械改成说明书。只有影响因果或连续性的明确问题才据实修正；未核实的疑点登记为待核，不擅自改设定。

融梗或润色按用户指定范围处理，检查人物身份、年代、当场目的和情绪；候选须给具体原场位置与替换文本。没有核实传播情况，不把普通熟语冒称当下热门网络梗。不把喜剧要求扩展到无关的紧张或悲伤场次。

## 每批保存与交付

完成一批后保存本版本正文、四份五场概括（尾批按实际范围）、对应、检查及交接，更新本版本主线和当前状态；保留必要人物与手法变化。路径统一见 workspace-layout.md，不按每批复制整套资料，不每批新建一个专用打包脚本。

更新项目索引的实际已写、已检查、已采用范围及下一起点；部分写完也记录成功保存点，检查未完就标未完。用户改为讨论时，不能把已经存在的新批漏出索引，也不能把新批登记成已验收。

需要五场阅读版或合集时，从唯一正文生成到 `交付/版本/` 并核对精确内容；源正文未改变则不重新生成全部历史批次。程序只证明范围、格式、路径及内容一致，剧情检查仍须回读正文。最终给正文入口、实际覆盖与剩余事项，不在聊天重复整篇和全部技术报告。
