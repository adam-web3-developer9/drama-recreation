# 网文改编

按“确定本次任务 → 原文分块与读取 → 必要分析和方案 → 每批 20 场写作 → 检查与保存”执行。只走本次需要的阶段，已有有效成果直接复用。目录使用 [workspace-layout.md](workspace-layout.md)，状态记录使用 [project-records.md](project-records.md)。

## 先判断用户要哪一步

| 本次要求 | 执行范围 |
| --- | --- |
| 先拆分、先处理开头若干字/章 | 只机械拆分、保存来源清单与素材索引；不把拆分当分析，不起草改编正文 |
| 分析、预计能改多少场/多少字 | 读取所需原文后分析或给有依据的区间估算；场数不是章数，估算不是最终承诺 |
| 首次写正文 | 先完成创作方案，按 SKILL.md 取得确认或明确跳过；已有确认方案直接复用 |
| 继续下 20 场或一次写更多场 | 接当前指定版本，按 [batch-writing.md](batch-writing.md) 在当前会话每批最多 20 场串行完成，不新建子代理 |
| 逐集审查、局部修订 | 完整对照指定各集对应原文章段与整集现稿，再局部修补；阅读范围与改写幅度分别限定，不仅检查已有候选 |
| 先想想改哪里、融什么梗、给候选 | 只给定位、原因和候选对白/动作，保存到 `方案/修改候选_版本_范围.md`；不顺手改正文 |

写作期间用户明确改为“先思考、先讨论”时，先记录原任务已经保存的场次、尚未核验范围和下一步，暂停正文写入及润色，处理新的讨论范围。讨论不是批准候选；明确要求落实后再按指定范围改稿。“只改这里”也不授权顺带润色整批。

## 原文分块：按章，不把章改叫场

先看素材索引及原文件章节结构，区分全书、已拆分、已读和本批需要的范围。原文很长时，先用脚本扫描章节标题和位置，按实际原章每五章保存一份至 `参考素材/来源/原文拆分/`，末组不足五章按实际范围命名；用户另有分组要求时遵从。扫描标题不表示已读正文。

用户指定“约五万字”等范围时，以最接近目标的完整章节边界截取并报告实际数量；明确要求不超过时选上限内的完整章节。说明字数口径，不把非空白字符数称为纯汉字数。这是用户指定的原文阅读窗口，不是所有改编都必须先读五万字。

拆分保留原文和章号，不润色、不摘要替换；清单记录源文件版本/指纹、章节标题与定位、各文件范围、下一章起点。核对拼接可还原所选原文、无遗漏或重复、源文件未变。复用现有可用脚本；需要编写时放入来源的 `工具/`，只负责拆分和拆分清单，不能重写创作项目索引或确认状态。重跑不得覆盖不同版本的已有成果。

无可靠章节标记时用原有段落或可回查位置分块并说明，不编造章号。没有正文只有大纲时按大纲改编，明确资料边界。

## 读取与最小必要分析

完整读取本批对应章段；事件跨分块时补齐起因和结果，后文只按承接需要扩读。逐集审查并局部修订时，每集同时完整读取对应原文章段和整集现稿，包括未改部分；先从原文辨认关键事件及叙述作用，再与现稿对照，不能由已有候选限定审查范围。局部修订限制改写幅度，不缩小用户要求的完整审查范围；明确只查某段时按该段处理。

在既有检查记录中记实际完整实读范围、原文定位与版本。工具输出截断时补读缺段；摘要、搜索命中、标题扫描、字数或指纹核验均不替代正文实读。同一会话中已实际读到且仍可用、版本未变的内容直接复用；压缩后按索引恢复必要内容。

来源分析保存在 `参考素材/来源/分析/`：人物与核心设定、主线总览和本批需要的证据。按原著章段定位，不为了套“五场概括”把小说章节冒称短剧场次。五场概括用于已经存在的剧本场次。区分原著事实、分析判断、用户指定修改及拟新增内容，只补当前缺项，不每批重做全书分析。

先确认主角想得到什么、阻力来自哪里、观众期待什么，以及关键场面的前置条件。保留角色稳定性格和行为选择、关系性质与成长过程；亲属合作、生活压力、资源获取等按实际原著处理，不为短剧化统一增加恶亲戚、村霸或受辱打脸。

有指定对标案例时按 [case-alignment.md](case-alignment.md) 选取本批阶段的完整事件；没有案例不额外寻找。未授权剧情重构时，原著提供剧情，案例提供指定写法；用户明确融合时才重构剧情和关系，并标明各来源贡献。

## 方案与本批安排

首次方案按 SKILL.md 包含大纲、核心主线、人物关系、世界观与改编取舍，存入 `方案/创作方案_版本.md`，确认状态登记项目索引。局部原著只能支持该范围的规划，未读后文和连载未完结处不编造原作结局。估算后续场数、字数时给出依据与可调整区间，不反向凑字数、固定每章场数或把每场强行写成一集。

获准正文后，只细化当前最多 20 场的章段对应，保留整体阶段方向；对应记录保存在 `稿件资料/版本/写作对应/第A-B场.md`。同一文件先记规划，出稿后补实际落地与必要修正，不另造多套“安排、写前、写后、最终”文件。

每场简记原著章段、本场行动与结果、改编处理及下一场承接。合章、拆章、前移与删并按戏剧作用安排：

1. 保留承担立人、关系变化、情绪积累或兑现的事件；重复说明可压缩，不能省掉关键铺垫。合并人物须在授权范围内核对身份、动机及知情。
2. 用完整交锋和局面变化确定场界，按用户实际要求组织集界；没有付费卡点要求不额外设置。章、场、集分别计数。
3. 重排时检查人物当时知不知道、能不能做、为什么现在做；新增行动来自已有设定和动机，不靠突然来人或凭空物证补因果。
4. 将内心、前世履历、背景知识转成可见行动、反应和必要的短信息；专业知识只保留影响当下选择的部分，不改成角色讲课。

## 叙述转译、行动过程与情绪兑现

改编保留的不只是“发生了什么”，还包括观众怎样看懂行动、经历悬念并感受结果。以下判断用于本批关键事件，不要求每句原文填表，也不要求所有场次加长。

### 先辨功能，再决定删改

原著的内心、作者说明、经验知识和百科插叙分别判断：

- 承担动机、判断、人物关系、情绪积累或后果的叙述，要找到新稿里的具体承载。优先用行动及其结果、对象的反应、空间或道具证据、当场短对白，必要时用有原文依据的记忆画面；画面难以清楚传达且有独立作用的信息，可保留简短内心声或旁白，不重复画面，也不为去掉OS让角色讲履历。
- 检查没读过小说的观众能从剧本获得哪条必要信息、能否理解人物为何此刻这样选择。看一眼、沉默或微笑可表达情绪，不能自动交代未出现的经历和事实；只写“想到、意识到”或作者核账式解释而没有可呈现承载，不算完成转译。
- 同一结论的重复说明、已展示过的重复过程和不影响当前理解的百科可以压缩或删除。不能因一句话没有直接推动外部事件，就删掉其关系或情绪作用。
- 对影响理解和感受的删改，在既有写作对应中简记“原文位置与作用 → 保留/转译/压缩/删除 → 新稿承载位置”。没有找到承载，不称已完成转译；确实可删则说明不再需要该作用的依据。
- 连接性的动作、停顿与口语可以演绎，但不得新增决定成败的能力、证据、习性、障碍或角色知情来替原著圆场。原文动作或数量有歧义时回读上下文，仍不清楚就标待核，不把候选解释当原作事实。

### 重要时刻写具体，关键过程写到能演、能看懂

先依据原文和本段戏剧作用找出重要时刻：如关键决定、能力首次奏效、风险升级、真相揭晓、胜负或关系转折、重要收获与情绪兑现。这些时刻的剧本应比普通过渡和重复过程更详细，写出当时的处境、决定结果的动作细节、对象反应、人物取舍和必要的情绪变化。不能只写“成功了”“很震惊”“十分高兴”，把具体表演留待分镜凭空补足；细节落在实际变化上，不靠堆形容词、无依据的波折或重复反应加字数。

对首次展示核心能力、改变局面的交锋、风险应对或关系转折，检查“外界变化—对象/人物反应—判断或选择—行动—结果确认”是否连得上。对象也可以是动物、环境、器物或身体状况，不为凑对抗强加反派；这是一种核对方法，不是每场固定五步的模板。

不要用一句“顺利办成”“抓住后带回”等结果概括，吞掉决定时机、策略和悬念的过程。多个动词挤在一条动作里不等于写足：观众应能辨认哪一步触发下一步，人物是在应对什么，以及结果何时确定。用有效动作和反应展开，不靠形容词、反复握拳变脸或无关波折撑长。

器物功能、技巧或处理过程决定剧情结果时，写清对象起初的状态、关键操作带来的变化及结果证据，不能只报名称或从原物直接跳到成品。保留观众理解所需的细节，不扩成与剧情无关的尺寸、配方或操作百科。

第一次具有戏剧作用的完整过程宜让观众看懂；后续同类重复可压缩，但新阻力、新选择或新的情绪回报仍要展开。不是第一次一律长、以后全部短。

### 让结果在人身上发生

收获、胜利、失去或关系变化发生后，检查原著中谁付出、谁承受风险、谁实际受益，以及谁发现结果、怎样确认和回应。主角已经笑了，不代表家人、伙伴或受礼者的关系回报已经承载；按原著或当前剧情的作用保留相应人物接住结果的具体动作或短回合，不要求人人轮流反应。按剧情保留必要的惊喜、失落、犹豫、分享、亲近或余味，不在结果出现后立刻转成报数和安排下一项事务。结果确认与情绪回报可以在同一动作中完成，不必额外加一场。

对关键段落，把预期观众感受对应到实际动作、对白、声音或信息变化；不能只在分析里写“紧张、喜悦、温暖”，正文却没有相应过程。五场概括可以汇总事件，不能替代其中关键段的核查。现稿已有有效铺垫、转译或兑现时明确保留，不因局部不足判整段失效。

喜怒哀乐、压迫、恐惧等按当前处境取用，不设情绪配额、固定反转次数或强度分数。有案例时回读对应完整事件，借其触发、反应与兑现方式，不搬入不属于原著的人物冲突。

### 节奏由内容决定

先明确关键动作、反应、理解和情绪落点，再估时或拆分镜。出手可快，观察、犹豫、结果确认与人物反应按需要留出空间。无对白的有效行动不是自动可删的氛围；不为台词密度硬添陪聊人物，也不靠静止空镜或慢动作拉长薄弱内容。

用户指定时长时，先说明该时间内能否完成所需内容及取舍；单条生成时长上限不等于完整事件的时长上限。不按场数、字数或固定镜数均摊秒数，也不以各集新增镜数相近判断修订是否充分。用户只要求剧本或修改候选时，不擅自生成分镜；若评估某条分镜过快，须核对相邻镜是否共同承载事件，未读取时标明证据边界。

局部修改候选应给出原文依据、现稿定位、保留项、具体可替换的对白/动作及前后接续，区分原文事实与演绎。只给候选时不覆盖正文，也不把候选登记为已采用。

## 串行起草与回查

承接写作先按 continuation.md 与 batch-writing.md 读取工作底稿首尾正文、中间概括及必要原场，最近窗口落在上一批工作稿结尾。已确认方案不因换批重复确认。总请求中的后批可承接同一待采用版本，自动串联不等于用户采用；另一次明确“接着这版继续”的采用依据按 SKILL.md 记录。

每批按 `script-format.md` 写完整正文至 `正文/版本/第A-B场.txt`，不以梗概替代。先从完整原文向现稿查关键动机、铺垫、判断、过程和情绪结果的承载，避免只检查已经写出的内容；再从现稿向原文及相邻剧情查新增表达是否有依据。沿用既有写作对应，注明跨场承载或合理删并的依据，不另建逐句台账。

对删并、改写或补写的关键动作，核对执行者、指代对象、时间、持有人、完成程度及物件前后状态；动作前提须在当前稿成立，不能沿用已被改掉的原文前提。后面的回述与前面展示的同步或先后顺序一致。修订后回读完整受影响事件及必要相邻场，也检查本集未改部分是否冲突。按 checks.md 区分必要修复、可选增强和有效保留，无缺口可以不新增。

事实核对要区分“原著已证实矛盾”和“自己的理解还不完整”：数字有疑问时先回读类别、单位、前提与上下文，不能仅凭推算判原著漏账。对白中的夸张、口语省略和人物误解按情境判断，不把顺口台词机械改成说明书。只有影响因果或连续性的明确问题才据实修正；未核实的疑点登记为待核，不擅自改设定。

融梗或润色按用户指定范围处理，检查人物身份、年代、当场目的和情绪；候选须给具体原场位置与替换文本。没有核实传播情况，不把普通熟语冒称当下热门网络梗。不把喜剧要求扩展到无关的紧张或悲伤场次。

## 已有分镜或视频项目的局部交接

获准落实局部修订后，保留唯一正文与现有编号，记录替换段、保留段和受影响镜头。用户要求同步应用或制作时，将最终文本对应到当前实际镜头，核对已排任务是否仍使用修改前内容，并通过所用应用的正式操作能力处理。正文通过、应用同步、制作排程和视频完成分别记录；接口、计费及重试规则归操作技能。仅修改剧本或Skill不自动触发生图、生视频。

## 每批保存与交付

完成一批后保存本版本正文、四份五场概括（尾批按实际范围）、对应、检查及交接，更新本版本主线和当前状态；保留必要人物与手法变化。路径统一见 workspace-layout.md，不按每批复制整套资料，不每批新建一个专用打包脚本。

更新项目索引的实际已写、已检查、已采用范围及下一起点；部分写完也记录成功保存点，检查未完就标未完。用户改为讨论时，不能把已经存在的新批漏出索引，也不能把新批登记成已验收。

需要五场阅读版或合集时，从唯一正文生成到 `交付/版本/` 并核对精确内容；源正文未改变则不重新生成全部历史批次。程序只证明范围、格式、路径及内容一致，剧情检查仍须回读正文。最终给正文入口、实际覆盖与剩余事项，不在聊天重复整篇和全部技术报告。
