# 统一工作目录

所有模式使用本页唯一目录规范。工作区位置由用户指定；目录名和职责统一，不探测或兼容旧项目结构，不自动迁移旧文件。用户自行迁移后，从新索引恢复；缺少新索引时盘点标准目录内的实际文件补建，不回退旧路径，不把缺少索引误认为没有成果。

## 工作区：参考素材与创作项目分开

```text
工作区/
├─ 工作区索引.md
├─ 参考素材/
│  └─ 来源名称/
│     ├─ 素材索引.md
│     ├─ 原始素材/          原小说、原视频、原剧本、字幕和原附带信息
│     ├─ 原文拆分/          小说按原章拆分；章节清单放这里
│     ├─ 还原稿/            视频还原的逐集剧本
│     ├─ 分析/              人物、主线、五场概括、手法；标明已读范围
│     ├─ 工作记录/          来源证据、帧图、音频、OCR、ASR及核验记录
│     └─ 工具/              仅服务该来源的脚本
├─ 创作项目/
│  └─ 目标剧名/
│     ├─ 项目索引.md
│     ├─ 方案/              创作方案_v1.md、创作方案_v2.md、修改候选等
│     ├─ 正文/
│     │  └─ v1/            第001-020场.txt、第021-040场.txt
│     ├─ 稿件资料/
│     │  ├─ 采用记录.md
│     │  ├─ 当前采用状态.md
│     │  └─ v1/
│     │     ├─ 人物与核心设定.md
│     │     ├─ 主线总览.md
│     │     ├─ 当前剧情状态.md
│     │     ├─ 推进情绪与表现手法.md
│     │     ├─ 五场概括/
│     │     ├─ 写作对应/
│     │     ├─ 批次交接/
│     │     └─ 检查记录/
│     ├─ 交付/              从正文生成的合集、五场阅读版、导出包
│     ├─ 工作记录/          任务历史、读取记录及临时工作文件
│     └─ 工具/              仅服务本项目的脚本
└─ 工具/                   真正跨项目复用的通用脚本
```

仅按实际产出创建目录，不预建整套空文件夹。正文扩展名遵从用户格式要求；统一的是归属和版本，不强制把所有正文转为某一格式。没有外部参考的原创项目可不建参考素材；只处理来源时可不建创作项目。

参考来源名称与目标剧名分开：复刻新剧不能塞进参考剧目录；多剧融合的目标项目与所有来源平级引用。原著和同名改编剧也分别位于参考素材与创作项目中。书名、工作剧名调整只更新显示名和索引，不能擅自新建一套重复项目或挪文件。

## 文件归属与唯一正文

- 每个来源只存一份原始素材和源分析，各项目通过相对链接引用。分析结论不能混进原文拆分或还原稿。
- 每个版本、每段场次只有一份可编辑正文，保存在 `正文/版本/`。每 20 场是执行与主稿保存单位；五场概括保存在 `稿件资料/版本/五场概括/`，两者不是同一个东西。
- 用户需要五场阅读版时，从已核验正文机械提取到 `交付/版本/五场阅读版/`；合集、导出包也在 `交付/版本/`。这些都是派生交付件，不独立改写；主稿变化后重新生成并核对内容一致。
- 人物、主线和当前状态按版本维护，不再每 20 场复制一整套；每批只新增五场概括、写作对应、检查记录与简短交接，更新本版本现状。交接保存批末快照，不能冒充一直有效的最新状态。
- 采用状态由 `稿件资料/采用记录.md` 记录场次、正文版本/路径、用户依据；`当前采用状态.md` 只从已采用的版本与范围派生。跨版本采用可逐段引用。新稿可继续串联，但不混进已采用事实。
- 文件名用版本和范围，不把“待确认”“已采用”这种会变化的状态写进新文件名。状态在索引和采用记录维护；方案确认状态由项目索引维护。版本文件不因采用而搬家或改名。
- 脚本不散落工作区或剧目根目录；技术核验 JSON、抽帧和中间文件不放进正文或方案目录。根目录以索引为入口，不堆所有批次报告。

## 三个导航入口

**工作区索引**只列参考来源和目标项目、简介、索引链接，不重复逐场状态；源素材与新故事分栏展示。

**素材索引**说明原始文件、版本、章/集总量，以及“已拆分、已实际读取、已还原、已分析”的各自范围；列拆分清单、还原稿、分析和证据入口。扫描目录或机械拆分不等于内容已读。

**项目索引**只保留一份当前状态：最新用户任务、方案确认、当前工作稿、采用范围、已写/已检查/未完成范围、下一起点与正文入口。正文与资料定位表见 [project-records.md](project-records.md)。历史任务详情放 `工作记录/任务历史.md`，不得一批接一批在首页堆出多个相互冲突的“当前状态”。

项目索引必须同时能回答“现在该读哪个稿”和“下一步还缺什么”。用户临时改为讨论或评估时，登记已保存的中间稿及待检查范围，不让首页还停在上一个已交付批次。

## 引用与工具边界

优先使用相对路径，跨项目通过工作区标准目录引用；路径、版本与实际覆盖一起保存。工具通过明确的工作区/来源/项目路径参数定位，不依赖启动目录，不内置某本小说名或固定批次。生成工具只更新自己负责的拆分、合集或检查清单，不重写项目索引、方案确认或正文采用状态。

旧项目迁移不属于写作或分析的自动步骤，也不在本 Skill 中保留旧新目录映射。若用户给的是未迁移旧项目，只说明新规范所需位置或索引缺口；收到迁移后的标准位置再恢复，不静默向旧目录继续写。
